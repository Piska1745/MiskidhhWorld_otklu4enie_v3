ACCOUNTLOCK V3 — MiskidhhWorld
================================

Цель:
- Paper 1.21.4, Java 21.
- Блокировка по UUID.
- СТРОГАЯ блокировка по сетевому IP-адресу: любой другой аккаунт,
  подключающийся с того же публичного IP, тоже не сможет войти.
- Зашифрованное хранилище vault.dat (AES-256-GCM).
- IP не записывается в открытом виде: сохраняется HMAC-SHA256 отпечаток.
- Нет команды разблокировки в плагине.
- Восстановление записей предусмотрено только отдельной офлайн-утилитой.
- Отключение объявляется в общий чат с ником игрока, администратором и причиной.
- OP сам по себе не даёт права отключать аккаунты.

ОЧЕНЬ ВАЖНО ПРО СТРОГУЮ IP-БЛОКИРОВКУ:
Один публичный IP может принадлежать нескольким людям (дом, школа, общежитие,
офис, мобильный оператор, CGNAT). Поэтому строгий режим может заблокировать
невиновных игроков, которые используют ту же сеть. IP также может измениться.
Прокси/VPN и серверные прокси могут влиять на то, какой IP видит Paper.
Проверьте сетевую архитектуру сервера до включения этой функции.
Это не надёжный способ доказать, что два аккаунта принадлежат одному человеку.

ПРАВА LUCKPERMS:
По умолчанию обе permission имеют default=false:
  accountlock.disable
  accountlock.audit

Выдать право конкретному игроку:
  /lp user Admin permission set accountlock.disable true

Выдать право проверки статуса:
  /lp user Admin permission set accountlock.audit true

Наличие OP не даёт эти права автоматически. Команду отключения можно выполнить
только игроку с явным accountlock.disable. Консольная команда отключения
намеренно не поддерживается.

КОМАНДА:
  /accountlock disable <ник_онлайн_игрока> <причина>
  /accountlock status <ник_онлайн_игрока>

Цель должна быть онлайн, чтобы плагин мог получить её UUID и сетевой адрес.
Отключить самого себя нельзя. /unban не влияет на эту систему.

КЛЮЧ:
Перед запуском установите переменную окружения:
  ACCOUNTLOCK_MASTER_KEY
Она должна содержать ровно 64 шестнадцатеричных символа (32 случайных байта).
Один и тот же ключ нужен плагину и офлайн-утилите восстановления.
Не храните его в GitHub, папке плагина, обычных YAML-файлах или чатах.
Храните его в защищённом менеджере секретов и сделайте защищённую резервную копию.

Если ключ отсутствует или vault.dat повреждён, плагин переходит в fail-closed:
он отклоняет все входы до восстановления корректного ключа и файла.
Не удаляйте vault.dat.tmp вручную во время работы сервера.

СБОРКА ПЛАГИНА:
1. Установить JDK 21 и Gradle 8.x.
2. Открыть корень проекта.
3. Выполнить: gradle build
4. JAR появится в build/libs/AccountLock-3.0.0.jar
5. Положить JAR в plugins и перезапустить Paper 1.21.4.

ОФЛАЙН-УТИЛИТА ВЛАДЕЛЬЦА:
В папке recovery-tool находится исходник RecoveryTool.java.
Он не является плагином и не помещается в plugins.
Скомпилировать:
  javac RecoveryTool.java

Показать список записей:
  java RecoveryTool list /полный/путь/к/plugins/AccountLock/vault.dat

Снять блокировку офлайн (плагин при этом должен быть остановлен):
  java RecoveryTool restore /полный/путь/к/plugins/AccountLock/vault.dat UUID

Утилита удаляет запись выбранного UUID и записывает vault.dat заново с новым
случайным nonce и тем же ключом. IP-отпечаток этой записи также удаляется.
Перед операцией обязательно сделайте резервную копию vault.dat.
Утилита работает только с файлом, путь к которому вы явно указали.

ОГРАНИЧЕНИЯ БЕЗОПАСНОСТИ:
Нельзя гарантировать абсолютную необратимость, если технический администратор
имеет полный доступ к хосту, JAR, процессу Java, переменным окружения или бэкапам.
Шифрование скрывает содержимое файла, но не защищает от владельца машины.
Нельзя безопасно спрятать секрет в коде или в том же каталоге, к которому
имеют доступ те, от кого нужно защититься.
Перед использованием сделайте тестовый сервер и резервную копию.
